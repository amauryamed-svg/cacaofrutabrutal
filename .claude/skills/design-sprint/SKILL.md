# Design Sprint Framework

A five-day structured process for rapidly prototyping and testing product ideas with real users to de-risk critical business decisions. Based on Jake Knapp's methodology (Google Ventures — 150+ sprints with Slack, Uber, etc.).

## Core Insight
"Great solutions require both deep work and fast iteration." The sprint compresses months of development into a single week by forcing decisions and creating prototypes that generate honest user feedback before expensive development begins.

## When to Use
✓ High-stakes product decisions  
✓ Resolving team disagreements  
✓ Testing risky concepts before major investment  
✓ Validating new products  

✗ Problem is already well-understood  
✗ Team lacks buy-in  
✗ No access to real target users  

## Prerequisites
- Decision-maker present for the full week
- 4-7 diverse team members
- 5 target users recruited for Friday testing
- Uninterrupted time (no other meetings)

## The Five Days

### Monday — Map
**Goal:** Define the problem and target customer journey.
- Long-term goal: Where do we want to be in 2 years?
- Sprint questions: What could go wrong?
- Map the customer journey end-to-end
- Interview experts (team members, users, stakeholders)
- **Pick a target** — one specific moment on the map to focus on

### Tuesday — Sketch
**Goal:** Generate individual solution concepts.
- Lightning demos: 3-minute tours of inspiring products (not just competitors)
- 4-part sketching: notes → ideas → crazy 8s → solution sketch
- **Crazy 8s**: 8 sketches in 8 minutes (quantity over quality)
- Solution sketch: detailed, self-explanatory, anonymous

### Wednesday — Decide
**Goal:** Critique and select the best approach.
- Art museum: post all solution sketches on the wall
- Heat map voting: dot stickers on interesting parts (silent)
- Speed critique: 3 minutes per sketch
- Straw poll → Decider vote (one person has final say)
- Create a storyboard (15 panels = prototype blueprint)

### Thursday — Prototype
**Goal:** Build a realistic facade — NOT production code.
- "Goldilocks quality": realistic enough to get honest reactions, not so precious you can't change it
- Tools: Figma, Keynote, or even paper prototypes
- Prototype only what you'll test — not the full product
- By end of day: clickable prototype ready for testing

### Friday — Test
**Goal:** Interview 5 target customers and identify patterns.
- 5 interviews reveals ~85% of usability problems
- One interviewer + one note-taker per session
- Give the user a scenario: "Imagine you are..."
- Think-aloud protocol: "Tell me what you're thinking"
- Look for patterns across all 5 interviews (not individual reactions)

## Interpreting Results
| Pattern | Meaning |
|---------|---------|
| All 5 users succeed | Strong signal — proceed |
| 3-4 users succeed | Promising — iterate on friction points |
| 2-3 users fail on same step | Clear problem — redesign that element |
| All 5 fail | Wrong direction — back to sketching |

## Post-Sprint Decisions
- **Proceed** → Build with confidence
- **Iterate** → Another sprint on the specific failure points  
- **Pivot** → Return to Monday with new insight

## Key Principles
- Move from discussion to action by doing, not debating
- Time-boxing forces decisions (no "let's keep thinking")
- Real user feedback beats any internal opinion
- The Decider role prevents design-by-committee paralysis
